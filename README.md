# nba-clutch-2pa-3pa

This repository contains code to reproduce the analyses reported in
`main.tex` and `Supplementary_Material.tex` for the regular-season NBA clutch
shot-choice manuscript.

The workflow covers:

- construction of regular-season WP states and clutch shot-choice panels
- pregame Elo and empirical-Bayes team-context covariates
- regular-season WP GAM fitting, scoring, and fixed-protocol WP comparison
- doubly robust CATE estimation with XGBoost, LightGBM, and CatBoost
- BLP calibration/recalibration and pooled / walk-forward CATE surfaces
- late-clock diagnostics reported in the supplement

## Reproduction roadmap

The main regular-season reproduction path is:

1. Prepare regular-season raw inputs from `nba_data` under `data/nba_raw/`.
2. Build per-season processed tables and WP / shot-decision states.
3. Fit or load the adopted regular-season WP model and score shot states to
   construct `delta_wp`.
4. Build the clutch shot-choice panel used by the doubly robust learners.
5. Fit nested walk-forward CATE learners and export fixed hyperparameters.
6. Fit full-data learner-specific CATE models, assemble the ensemble, and
   rebuild the retained CATE figures.
7. Run the late-clock supplement diagnostics as needed.

The commands below follow this order. Full reproduction is computationally
large; the repository is intended to make the analysis repeatable, not to make
the full manuscript pipeline run in a few minutes after clone.

## Environment

Recommended Python version: 3.11. Python 3.12 was used in the cleanup
environment, but Python 3.11 is recommended for broader package-wheel
compatibility across `xgboost`, `lightgbm`, `catboost`, and `pyarrow`.

Local library folders are intentionally not part of the repository. Recreate
them from:

- `requirements.txt` for Python
- `requirements-r.txt` for R
- `ENVIRONMENT.md` for exact setup commands

Minimal setup:

```sh
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt

mkdir -p .r_libs_4.5
Rscript -e 'options(repos = c(CRAN = "https://cloud.r-project.org")); install.packages(readLines("requirements-r.txt"), lib = ".r_libs_4.5")'
export R_LIBS_USER="$PWD/.r_libs_4.5"
```

The analysis scripts use fixed default seeds for stochastic components unless
overridden by command-line arguments or environment variables. The main Python
DR/CATE wrappers default to `RANDOM_STATE=123`, figure subsampling defaults to
`--seed 123`, and the WP R scripts call `set.seed(123)`.

## Data

The workflow expects NBA play-by-play and shot-detail inputs derived from the
open-source `nba_data` repository. Large raw, derived, and model-output
directories such as `nba_data/`, `data/`, `models/`, and most of `results/` are
not intended to be committed to the public code repository.

Directory roles:

- `nba_data/`: optional local checkout of the upstream data repository.
- `data/nba_raw/`: raw regular-season CSV exports from `nba_data`.
- `data/processed/`: per-season core tables generated by `scripts/core/build_core_tables.py`.
- `data/wp/`: WP states, shot-decision states, and WP-scored shot states.
- `data/analysis/`: team-context files and the clutch shot-choice panel.
- `models/`: fitted WP GAM and optional locally trained model artifacts.
- `results/`: regenerated CATE, walk-forward, and figure-source outputs.

Place the raw regular-season CSV exports from the upstream `nba_data`
repository under `data/nba_raw/`. The simplest expected layout is:

```text
data/
  nba_raw/
    nbastats_2000.csv
    pbpstats_2000.csv
    shotdetail_2000.csv
    ...
    nbastats_2024.csv
    pbpstats_2024.csv
    shotdetail_2024.csv
```

Copying files is fine, but symlinking from a local checkout of `nba_data` is
usually preferable because it avoids duplicating large raw data. For example:

```sh
mkdir -p data/nba_raw
ln -s <local-nba-data-export-dir>/nbastats_2000.csv data/nba_raw/
ln -s <local-nba-data-export-dir>/pbpstats_2000.csv data/nba_raw/
ln -s <local-nba-data-export-dir>/shotdetail_2000.csv data/nba_raw/
```

Repeat for seasons 2000 through 2024. The core-table builder also accepts
regular-season filenames such as `nbastats_rs_2000.csv` and
`nbastats_2000_rs.csv` for `nbastats`, `pbpstats`, and `shotdetail` inputs, but
the `*_YYYY.csv` convention above is the canonical layout for this release.

After placing the raw files, build the regular-season intermediate data used by
the manuscript pipeline:

```sh
mkdir -p data/processed data/wp data/analysis models results

# Build per-season processed tables and WP/shot-decision states.
bash scripts/helpers/run_core_tables_per_season.sh
bash scripts/helpers/run_wp_features_per_season.sh

# Combine per-season WP and shot-decision states into the manuscript window.
python scripts/core/combine_wp_states.py --start-season 2000 --end-season 2024 --seasontype rs

# Build auxiliary team-context inputs required by the shot-choice panel builder.
python scripts/core/construct_team_shot_stats.py \
  --start-season 2000 \
  --end-season 2024 \
  --input-start-season 2000 \
  --input-end-season 2024 \
  --seasontype rs \
  --out data/analysis/team_shot_stats_2000_2024.parquet

python scripts/core/construct_cumulative_team_foul.py \
  --start-season 2000 \
  --end-season 2024 \
  --seasontype rs \
  --output data/analysis/cumulative_team_fouls_2000_2024_rs.parquet
```

Default downstream paths used by the scripts include:

- `data/wp/wp_states_2000_2024_rs.csv.gz`
- `data/wp/shot_decision_states_2000_2024_rs.csv.gz`
- `data/analysis/shotchoice_panel_clutch_rs.parquet`

If these downstream files are already present, the raw `nba_data` checkout does
not need to be included in the release archive.

## Compute requirements

The full pipeline was written for a workstation or Slurm environment. The
checked-in Slurm wrappers request resources on the order of:

- core table and WP feature construction: 25 CPU threads, 96 GB RAM, up to 48 hours
- WP shot-panel scoring: 16 CPU threads, 128 GB RAM, up to 48 hours
- nested walk-forward CatBoost: 1 GPU, 8 CPU threads, 48 GB RAM, up to 144 hours
- nested walk-forward XGBoost / LightGBM: 16 CPU threads, 64 GB RAM, up to 144 hours
- full-data CATE fitting: 1 GPU for CatBoost or 32 CPU threads for XGBoost / LightGBM

Actual wall time depends on hardware, local BLAS/threading configuration, and
whether intermediate files already exist.

## Main workflow

The high-level regular-season workflow is:

```sh
# Score shot states with the adopted WP model and build the clutch panel.
bash scripts/pipelines/run_rs_m0_k0_shot_panel.sh

# Estimate held-out CATEs by nested walk-forward.
bash scripts/pipelines/run_nested_walk_forward_catboost.sh
bash scripts/pipelines/run_nested_walk_forward_xgb_lgbm.sh

# Fit full-data learner-specific CATE models and produce ensemble surfaces.
# This wrapper submits Slurm jobs with sbatch.
bash scripts/pipelines/run_full_data_pipeline.sh
```

The full-data pipeline uses fixed hyperparameters exported from the
walk-forward outputs, fits final learner-specific CATE models, builds the
equal-weight ensemble, and writes CATE surface artifacts.

For Slurm users, scheduler-specific email notifications, node exclusions, and
account/partition choices should be supplied locally with `sbatch` options or
site-specific wrapper scripts. They are intentionally not hard-coded in this
public reproduction repository.

## Manuscript figure assembly

The retained manuscript figures are assembled from the CATE outputs above and
copied to the repository root with their manuscript filenames:

```sh
# Rebuild the held-out walk-forward ensemble surface.
python scripts/helpers/rebuild_wf_cate_surfaces_recalibrated.py \
  --outdir results/wf_cate_surfaces \
  --catboost-dir results/nested_wf_catboost_gpu \
  --xgb-dir results/nested_wf_xgb \
  --lgbm-dir results/nested_wf_lgbm

# Build the retained CATE PNGs under figures/.
python scripts/helpers/assemble_manuscript_cate_figures.py \
  --ensemble-dir results/full_data_ensemble_state_fixed_loso \
  --wf-dir results/wf_cate_surfaces \
  --figure-source-dir results/figure_source_data_revise1 \
  --panel data/analysis/shotchoice_panel_clutch_rs.parquet \
  --outdir figures
```

`run_full_data_pipeline.sh` / `run_full_data_ensemble_oos.sh` produce the
full-data ensemble CATE surfaces and model sign-agreement PNG. The assembly
helper then writes:

- `figures/figure1_full_data_t15_300_cate_surface.png`
- `figures/figure2_outer_fold_t15_300_cate_surface.png`
- `figures/figures1_cate_surface_0_15s_masked_n50.png`

## Key scripts

- `scripts/core/build_core_tables.py`, `scripts/core/build_wp_features.py`, `scripts/core/combine_wp_states.py`:
  regular-season state construction
- `scripts/core/construct_cumulative_team_foul.py`, `scripts/core/construct_team_shot_stats.py`,
  `scripts/core/build_shotchoice_panel_from_wp.py`: shot-choice panel construction
- `scripts/core/fit_wp_model.r`, `scripts/core/fit_wp_and_score_shots.r`: WP modeling
- `scripts/core/run_nested_walk_forward.py`, `scripts/core/train_full_data_selected_model.py`,
  `scripts/core/train_dr_learner.py`: DR/CATE estimation
- `scripts/core/calibrate_tau_cate.py`, `scripts/core/apply_tau_calibration_and_compare.py`:
  CATE BLP calibration and recalibration
- `scripts/core/average_cate_surfaces.py`, `scripts/core/plot_cate_surface_gcomp.py`,
  `scripts/core/summarize_cate_surface_sign_agreement.py`: CATE surface summaries
- `scripts/core/audit_forced_late_down3_wp_cells.py`, `scripts/core/make_four_cell_uncertainty.py`,
  and `scripts/helpers/local_tail_*` / `plot_observed_*`: late-clock
  supplement diagnostics
